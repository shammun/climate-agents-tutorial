1. Project rules
AGENTS.md · CLAUDE.md · GEMINI.md
  • briefing sheet for the whole project
  • sets tone, constraints, file conventions
  • every agent reads this at the start
⏰ loaded: every session, every agent

Example CLAUDE.md rules that apply to every agent in the project:

Never delete files in data/raw/.
All figures must be saved to figures/
  with an ISO-date prefix: YYYY-MM-DD_name.png
Use CF conventions for all NetCDF output.
Return structured JSON in the final answer.

These rules cannot be overridden by individual agents — they're the constitution of your project.

💡 Keep project rules short and absolute. If a rule has exceptions, it doesn't belong here — put it in the agent definition instead.

2. Agent definitions
.claude/agents/*.md · .codex/agents/*.toml
  • one specialist per file: role, tools, model
  • each has a name, description, tools list
  • keeps specialists focused and testable
⏰ loaded: only when that agent is delegated to

Example .claude/agents/data-fetcher.md:

name: data-fetcher
description: Downloads ERA5 reanalysis via the CDS API
tools: [bash, write_file]
skills: [era5-download]
---
You download ERA5 pressure-level data for the
date range the caller specifies.
Always save to data/raw/era5/ as NetCDF4.

The frontmatter (above ---) is machine-readable. The body (below) is the LLM's instruction manual.

💡 The description field is what Claude reads to decide which agent to delegate to — make it precise and distinctive.

3. Skills
.claude/skills/<name>/SKILL.md
  • reusable manual + optional helper scripts
  • one skill teaches one capability
  • examples: era5-download, netcdf-conventions
⏰ loaded: only when explicitly invoked

Add skills: [era5-download] to an agent's AGENTS.md entry. The SKILL.md file loads at that moment and might contain:

- Full CDS API authentication steps
- cdsapi Python code templates
- Variable name mappings (t2m, u10, v10…)
- Instructions for handling API rate limits
- Helper scripts: download_era5.py

The skill author maintains it once; every agent that lists it gets the latest version automatically.

💡 Skills are reusable across projects. A well-written era5-download skill can serve a dozen different projects with no changes.

4. Permissions
.claude/settings.json
  • hard limits no agent can override
  • controls allowed tools and blocked paths
  • applied before every tool call, always
⏰ applied: always, before every tool call

Example .claude/settings.json:

{
  "allowedTools": ["bash","read_file",
                   "write_file","python"],
  "blockedPaths": ["data/raw"],
  "maxConcurrentAgents": 4
}

The blockedPaths setting prevents any agent from modifying raw data, even if it tries. This is enforced by the harness before the tool call runs — the agent never even gets to attempt it.

💡 Always block your raw data directory. It's the best insurance against an agent accidentally overwriting a 50 GB download.
