🏗️ The Four Building Blocks

Every AI coding tool uses these same four ideas — only the filenames differ

💡 Think of it as the employee handbook — everyone reads it on day one, every session.
📋
1. Project rules
AGENTS.md · CLAUDE.md · GEMINI.md
  • briefing sheet for the whole project
  • sets tone, constraints, file conventions
  • every agent reads this at the start
⏰ loaded: every session, every agent
💡 Like a job description — written once, re-used every time that specialist is needed.
🤖
2. Agent definitions
.claude/agents/*.md · .codex/agents/*.toml
  • one specialist per file: role, tools, model
  • each has a name, description, tools list
  • keeps specialists focused and testable
⏰ loaded: only when that agent is delegated to
💡 Skills keep agents small and composable — load only what you need, pay only those tokens.
🔧
3. Skills
.claude/skills/<name>/SKILL.md
  • reusable manual + optional helper scripts
  • one skill teaches one capability
  • examples: era5-download, netcdf-conventions
⏰ loaded: only when explicitly invoked
💡 The safety net — even a rogue agent can't break these hard limits.
🔒
4. Permissions
.claude/settings.json
  • hard limits no agent can override
  • controls allowed tools and blocked paths
  • applied before every tool call, always
⏰ applied: always, before every tool call
🌟 Did you know? The same four-block structure works in Claude Code, Codex, Gemini CLI, and others — learn it once and you understand them all!
