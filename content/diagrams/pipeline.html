# The skill teaches this cdsapi pattern:
import cdsapi
c = cdsapi.Client()
c.retrieve('reanalysis-era5-single-levels', {
    'product_type': 'monthly_averaged_reanalysis',
    'variable': '2m_temperature',
    'year': str(year), 'month': [f'{m:02d}' for m in range(1,13)],
    'format': 'netcdf',
}, f'data/raw/era5/t2m_{year}.nc')
Raw files are write-once. All downstream agents treat them as read-only, so your original data is always recoverable — even after a failed analysis run.

⚠️ What if this step fails?

The main agent catches the FAIL status and re-runs with corrected parameters (e.g. a narrower date range, different variable name). The CDS API has a queue — downloads may take minutes to hours for large requests.

✅ Checks performed

  • Spatial coverage: does the grid match the requested domain?
  • Time coverage: are all 12 months × all years present?
  • NaN fraction: is it less than 5% per file?
  • Units: is t2m in Kelvin (not Celsius)?
  • File size: greater than 100 KB? (guards against empty downloads)

QC Python snippet

import xarray as xr, json, glob

results = []
for f in sorted(glob.glob("data/raw/era5/t2m_*.nc")):
    ds = xr.open_dataset(f)
    nan_frac = float(ds.t2m.isnull().mean())
    units_ok = ds.t2m.attrs.get("units", "").startswith("K")
    results.append({
        "file": f, "nan_pct": round(nan_frac * 100, 1),
        "units": ds.t2m.attrs.get("units", "MISSING"),
        "ok": nan_frac < 0.05 and units_ok
    })

verdict = "PASS" if all(r["ok"] for r in results) else "FAIL"
# Return as JSON to the main agent
print(json.dumps({"status": verdict, "files": results}))
If status is FAIL, the main agent re-runs the fetcher with corrected parameters. The pipeline never advances past a failed QC — this is the safety gate for all downstream analysis.

⚠️ Common FAIL reasons

Wrong units (°C instead of K) — check CDS request format. Missing months — widen the date range. High NaN fraction over ocean — usually a masking issue; request "land_sea_mask" variable to investigate.

data/processed/*.nc

📥 Reads from

  • data/raw/era5/*.nc — via xarray multi-file dataset
  • QC report — checks that status is PASS before proceeding
  • Analysis spec from main agent: season (JJA), stat (trend), domain

📤 Writes to

  • data/processed/jja_mean.nc — mean temperature per year per cell
  • data/processed/trend.nc — slope (K/yr) + p-value + R² per cell
  • Both files include CF attributes and a history global attribute

🔧 Tools

  • python — xarray, numpy, scipy.stats
  • read_file — opens NetCDF and QC report
  • write_file — saves the processed outputs

📐 Computations

  • Select JJA: ds.time.dt.month.isin([6,7,8])
  • Group by year: jja.groupby("time.year").mean()
  • Trend per cell: scipy.stats.linregress(years, values) → slope, p-value, R²
  • Apply CF attributes: units="K yr-1", standard_name="trend"

Core analysis — full working snippet

import xarray as xr, numpy as np
from scipy import stats

# Load all years at once with mfdataset
ds = xr.open_mfdataset("data/raw/era5/*.nc", combine="by_coords")
jja = ds.t2m.sel(time=ds.time.dt.month.isin([6,7,8]))
mean = jja.groupby("time.year").mean("time")  # (year, lat, lon)

years = mean.year.values.astype(float)
slope = xr.apply_ufunc(
    lambda y: stats.linregress(years, y)[0],
    mean, input_core_dims=[["year"]], vectorize=True
)
pval = xr.apply_ufunc(
    lambda y: stats.linregress(years, y)[3],
    mean, input_core_dims=[["year"]], vectorize=True
)

slope.attrs = {"units": "K yr-1", "long_name": "JJA temperature trend"}
pval.attrs  = {"units": "1",      "long_name": "p-value of linear trend"}
xr.Dataset({"slope": slope, "pval": pval}).to_netcdf(
    "data/processed/trend.nc")
All output NetCDF files include CF standard_name, units, and a history attribute recording the agent run date — so results are always traceable and reproducible.

⚠️ What if this step fails?

Memory error on large datasets? Use chunks={"time": 12} in open_mfdataset to enable Dask lazy loading. If scipy gives NaN slopes (too few years), check the QC report for coverage gaps.

Trend map snippet

import matplotlib.pyplot as plt
import cartopy.crs as ccrs, cartopy.feature as cfeature
import xarray as xr
from datetime import date

ds = xr.open_dataset("data/processed/trend.nc")
fig, ax = plt.subplots(subplot_kw={"projection": ccrs.PlateCarree()},
                       figsize=(12, 6))
slope = ds.slope * 10  # K/decade for readability

im = ax.pcolormesh(ds.longitude, ds.latitude, slope,
                   cmap="RdBu_r", vmin=-0.5, vmax=0.5,
                   transform=ccrs.PlateCarree())
# Stipple grid cells where p < 0.05
sig = ds.pval < 0.05
ax.scatter(ds.longitude.values[sig.values],
           ds.latitude.values[sig.values],
           s=1, c="k", alpha=0.3, transform=ccrs.PlateCarree())

ax.add_feature(cfeature.COASTLINE, linewidth=0.6)
plt.colorbar(im, ax=ax, label="JJA T trend (K decade⁻¹)")
fig.savefig(f"figures/{date.today()}_trend_map.png", dpi=300)
ISO-date filenames let you run the pipeline multiple times without overwriting results — each run produces its own dated set of figures, making experiments traceable.

⚠️ What if this step fails?

Cartopy projection errors usually mean lat/lon coordinates are not 1-D — use ds.assign_coords to reshape. Missing colourmap? Use matplotlib.cm.get_cmap("RdBu_r"). If Cartopy is not installed, the skill falls back to a basic imshow plot with a warning.

📥 Reads from

📤 Returns (to main agent)

  • VERDICT: READY — all checks passed, pipeline complete

🔧 Tools

  • read_file — opens processed files for inspection
  • bash — runs ls -lh figures/ to check file sizes
  • No write_file — strict read-only by design

🧐 Checks performed

  • Both PNG files exist and are > 50 KB (guards against blank exports)
  • Trend range: slope values between −1.0 and +1.0 K/yr (physical plausibility)
  • Significance: 5–80% of domain has p < 0.05 (too low = no signal, too high = suspicious)
  • Time-series covers the full requested date range (no truncation)
