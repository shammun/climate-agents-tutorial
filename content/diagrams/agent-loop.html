🎯 Task
  • Your request or goal
  • e.g. Analyze SST anomalies for 2023

A task can be as simple as "Analyze SST anomalies for 2023" or as complex as a multi-page brief. The agent reads it verbatim on every loop iteration — so the more specific you are, the better.

✅ Good task (specific):

"Download ERA5 2m temperature for 2000–2023 over
Europe (10W–40E, 35N–70N) at 0.25° resolution.
Compute JJA seasonal mean per year per grid cell.
Fit a linear trend. Plot a filled-contour trend map
with CartoPy, stipple p < 0.05 cells, and save to
figures/YYYY-MM-DD_trend_map.png at 300 DPI."

❌ Bad task (vague):

"Analyze European temperature data and make a figure."

The vague task forces the agent to guess domain, variable, season, stat, and output format — leading to wrong assumptions, re-runs, and wasted tokens.

💡 Include file paths, variable names, expected outputs, and format details directly in the task. The agent won't guess — and neither should you.

🧠 Model (LLM)
  • reads: instructions + task + ALL tool results so far
  • decides: which tool to call next
  • or: writes final answer when finished
  • ⚠ The model never executes — it instructs

The model never touches files directly. It outputs a structured tool call:

{"tool": "bash", "input": "python compute_trend.py"}

…and the harness executes it, returning the result to the model. The model then decides the next tool call — or writes a final answer to end the loop.

What the model sees on each iteration:

System: [CLAUDE.md + agent instructions]
User:   [original task]
Asst:   [tool call 1]
User:   [tool result 1]
Asst:   [tool call 2]
User:   [tool result 2]
...     [entire history, every time]

This means a chain of 20 tool calls = the model re-reads the full history 20 times. Keep loops tight — focused subagents with limited tool lists finish faster and cost less.

💡 Keep tasks focused. A chain of 20 tool calls means the model re-reads everything 20 times. Split long workflows across subagents — each gets a fresh, small context.

Common climate science tools and what they do:

bash        → run Python / NCO / CDO scripts, check files
read_file   → inspect NetCDF headers and metadata
write_file  → save processed data and results
python      → run inline analysis snippets
search_web  → look up CF standard names, API docs

The tool list is declared in AGENTS.md under tools: — the agent can only call tools listed there. Any unlisted tool is blocked by the harness before the call runs.

✅ Final Answer
  • returned to the caller
  • the agent stops here
  • working steps stay private

The agent stops when it outputs plain text with no tool call. Everything it ran — every bash command, every intermediate file, every failed attempt — stays hidden inside the agent. The caller only ever sees this final message.

❌ Unstructured final answer (hard to chain):

"I downloaded the ERA5 data and computed the trend.
The trend map is saved. It looks reasonable."

✅ Structured final answer (easy to chain):

{"status": "PASS",
 "files_written": ["data/processed/trend.nc",
                   "figures/2024-01-15_trend_map.png"],
 "trend_range_K_yr": [-0.08, 0.14],
 "significant_fraction": 0.34,
 "warnings": []}

That isolation is what makes agents composable: one agent's messy 20-step work becomes another agent's clean JSON input.

💡 Always ask your agent to return structured JSON in the final answer — it makes chaining agents, error-checking, and automation dramatically easier.
