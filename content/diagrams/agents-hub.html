🤖 Main agent
  • talks to you, plans, delegates
  • decomposes the task into focused sub-jobs
  • collects results and synthesises the final answer
  • 🎯 Sees the big picture — never does the detail work

The orchestrator writes a plan first:

Step 1: data-fetcher downloads ERA5
Step 2: data-qc validates the files
Step 3: climate-analyst computes JJA trend
Step 4: figure-maker plots the results
Step 5: results-reviewer checks outputs

Then it delegates Step 1, waits for the result (a file path), delegates Step 2 with that path, and so on. It never does the domain work itself — it only orchestrates.

💡 If a subagent returns FAIL, the main agent can re-run that step with adjusted instructions — automatic error recovery.

🔎 data-qc
  • checks data quality
  • own context · own tools
  • validates units, fill values, coverage
read_file · python

Tools: read_file, python. Read-only — cannot modify files.

Checks: spatial coverage (domain complete?), time coverage (no missing months?), fill value fraction (<5%?), units (K not °C?).

Returns structured JSON:

{"status": "PASS",
 "warnings": ["Nov 2003: 8% NaN over ocean"]}
💡 If status is FAIL, the main agent re-runs the fetcher with adjusted parameters — automatic quality gating.

📊 climate-analyst
Loads raw ERA5 → extracts JJA months → computes per-year seasonal means → fits linear trend per grid cell with scipy.stats.linregress → saves slope + p-value as CF-compliant NetCDF.
Never downloads or plots — pure data transformation.

Tools: python, read_file, write_file. Reads: data/raw/era5/*.nc. Writes: data/processed/*.nc

Example computation: load all years → extract JJA (June–August) → compute seasonal mean per grid cell → fit linear trend with scipy.stats.linregress → save slope and p-value as NetCDF with CF attributes.

💡 This agent never downloads or plots — it only transforms data. That tight scope makes it easy to test and replace.

📝 results-reviewer
  • reviews outputs · read-only
  • own context · own tools
  • writes the final verdict
read_file · bash

Tools: read_file, bash. Read-only — never writes data files.

Checks: do figures exist with non-zero size? Do processed files have expected variables? Are p-value maps consistent with trend maps?

Returns: VERDICT: READY or VERDICT: NEEDS_REVISION with specific reasons. The main agent uses this verdict to decide whether to publish or re-run.

💡 A read-only reviewer is your last line of defense. Because it can't write files, it can't accidentally corrupt the outputs it's checking.
